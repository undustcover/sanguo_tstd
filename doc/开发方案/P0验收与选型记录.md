# P0 收尾与技术选择

日期：2026-11-06

## 决定

采用 GDQuest Tactical RPG Movement 的 godot4 示例作为现阶段外部地图模块基础。不是完整战斗框架；内部结算、外部单位行动管理和持续状态将由本项目实现。

固定上游提交40023de94033ee649cd5d90033b7b6e003f0b554，开发引擎4.7.2.stable.official.ed1daf0bf，GDScript，Compatibility渲染。升级需要重新运行验收。

## 依据与成本

P0的A1—A8由自动检查、代码检查及用户实际操作验收覆盖。接入只需新增数据与面板层和小范围兼容修整，未重写地图选择移动主体。数据身份、指挥归属、成员状态及地图往返已可表达。

后续必须自建：带编制校验的军团/成员类型、十二格阵形界面、内部行动结算与目标合法性、外部单位逐个行动、存档和基础AI。当前移动示例没有提供这些系统。

C#备选已知需要适配默认阵营回合和预计算结算，并引入.NET工具链；本轮未实际运行或计时比较C#方案，不声称已证明总体成本更低。当前轻量方案已满足试改目标，因此不继续并行投入备选。若P1发现结算必须侵入地图移动核心，或出现难以消除的状态生命周期耦合，再重启选型。

## P1 首版规则（用户已确认）

1. 阻挡：所有可作战成员构成同列阻挡；失能武将、零可战斗兵力部队保留格位记录但不阻挡。
2. 待机：首版只允许无合法目标时待机，不加入主动待机和放弃行动。
3. 排序：首版交战开始时固定队列；交战中速度变化下一次交战生效；同速用可记录的随机种子复现。
4. 测试数值：先使用每成员固定测试攻击值，部队伤害减少可战斗兵力、武将伤害增加测试伤势；用户确认每次扣10兵、伤势+1、3点伤势失能，不提前加入正式伤亡换算。
5. 操作：双方先均由玩家逐个选择合法目标，便于验证；自动选敌作为后续独立功能。

以上已由用户确认，首版实现记录见P1实现与验收记录.md。三将八部队上限、最多四支指挥归属、重复位置及身份校验将作为数据约束加入；P0尚未实现这些校验。
