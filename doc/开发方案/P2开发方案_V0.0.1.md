# P2 外部战斗循环开发方案 V0.0.1

- 日期：2026年11月6日
- 状态：开发方案已建立；外部行动规则待用户确认，尚未开始P2实现。
- 前置基础：P0操作验收通过；P1首版用户验收通过，数据约束及边界自动检查完成。
- 规则来源：《战斗方案 V0.0.2》及P1用户确认补充；本文中的建议不自动成为规则。

## 一、目标与场景边界

在独立外部方格战场上，让双方多支军团按单位依次行动，完成移动、接敌、内部有限交战、返回战场、继续行动及整场结束的小循环。

探索场景为传统RPG场景，可进一步进入城镇、迷宫，属于P4工作。外部战场不是探索大地图；内部交战是两个外部单位接敌后的过程。内部演出加速/关闭为表现层需求，P2先使用逐次目标选择与日志，不引入动画制作。

## 二、已确定的基础

- 外部单位各占一格，独行武将与带兵军团共享操作方式。
- 外部按单位逐个行动，不采用一方全部行动完再轮到另一方。
- 外部行动额度与内部成员基础行动独立管理。
- 每次内部交战恢复可行动成员的基础行动，不恢复兵力或伤势。
- 内部使用P1已确认的排序、射程、阻挡、反击及待机规则。
- 兵力归零不拆散编组；失能成员保留数据，不能只用共享军团生命值表达战损。

## 三、P2实施前需要确认的规则

以下是建议方案，不能直接编码成既定玩法。用户此前只要求建立方案，尚未明确批准这些规则。

| 编号 | 决策 | 首版建议 | 需说明的边界 |
| --- | --- | --- | --- |
| R1 | 外部顺序 | 独立order字段降序，每轮开始固定队列 | 不使用内部速度；同序按稳定单位ID排列；跳过失能单位；双方交错只是测试配置结果，不强制一敌一我 |
| R2 | 移动与攻击额度 | 每单位每轮最多移动一次、攻击一次；攻击后结束行动 | 允许先不移动直接攻击；不允许攻击后移动；明确“结束行动”按钮；取消移动预览不扣额度 |
| R3 | 接敌距离 | 上下左右相邻一格 | 不包含斜角；外部接敌与内部射程各自判断 |
| R4 | 整场结束 | 一方所有外部单位无可作战成员即结束 | 双方均无可作战成员为平局；攻击后先完成内部结算，再检查战场结束 |
| R5 | 无可作战单位的占位 | 从外部占位表移除，保留数据及日志 | 不删除军团；内部零兵力/失能成员仍保留阵形记录 |
| R6 | 移动距离与地形 | 继续使用单位move_range、四向等成本移动，其他单位占位阻挡 | 确认范围应按实际可达路径步数计算，不能用直线曼哈顿距离代替绕行成本 |
| R7 | 测试操控与退出 | 双方均由玩家操作；正常交战结束后才能返回外部战场 | P1“测试中止”不能作为正式撤退；整场可通过明确的重开测试按钮重新加载初值 |

不加入外部撤退、攻击后再移动、地形伤害、隐藏单位等未定机制。若用户调整以上建议，应先更新本节和验收用例。

## 四、实现结构

1. 战场会话持有单位ID、阵营、位置、军团引用、外部顺序、移动/攻击额度及回合序号。军团数据仍由会话拥有，画面只引用，不在返回时重新生成。
2. 独立外部行动控制器管理当前单位、移动完成、发起交战和结束行动。GameBoard继续提供选择、路径与移动，不承担内部结算。
3. Encounter接收进攻/防守军团引用和本次种子。P2需要将P1测试界面改为可接收任意双方的可复用界面，移除对固定A/B及P0节点的依赖；保留P1测试入口。
4. 内部结算完成只回传结果并释放输入锁；战场控制器消费一次攻击额度、更新占位和胜负。重复点击及重复完成回调不得重复扣额度或重复发起交战。
5. 使用明确状态：等待指令、移动中、交战中、战场结束。交战/移动期间禁止其他单位操作，恢复时只开放当前状态允许的指令。
6. 种子、外部行动、内部事件和结果写入可观察日志。沿用临时伤害，不加入正式指挥惩罚与伤兵阵亡换算。

## 五、最小验证场景与实施顺序

场景使用小型方格战场、占位美术，双方各两支外部单位；至少一支为独行武将，其余为带兵军团。每支军团成员ID全局唯一，测试属性明确标注。

1. 确认R1—R7，建立固定测试配置和预期顺序。
2. 完成军团会话与外部行动控制器、当前单位和额度显示。
3. 接入当前单位选择、路径预览、移动确认/取消；修正必要的实际路径步数限制。
4. 接入相邻敌军选择及可复用内部交战界面。
5. 完成交战返回、额度消费、单位失能更新、回合推进及胜负。
6. 补齐重复输入与状态往返检查，人工完整打一场战斗并保存基线。

## 六、验收标准

| 编号 | 验收内容 |
| --- | --- |
| B1 | 双方至少各两单位、包含独行武将，顺序可观察且按已确认规则逐个行动 |
| B2 | 只能操作当前单位；移动实际路径不超过移动范围，占位与预览一致；取消不扣额度 |
| B3 | 只有合法接敌距离的敌方可发起交战；不能打友军、自己或已无可作战成员的单位 |
| B4 | 移动一次和攻击一次等额度按确认规则消耗；结束行动、回合恢复均正确 |
| B5 | 交战双方来自当前选定单位；进入交战后地图锁定；重复输入不重复触发 |
| B6 | 返回后位置及双方成员战损保留；攻击额度只消费一次 |
| B7 | 同一军团与不同敌军接连交战，内部行动每次恢复、战损不恢复；记录多次潜在反击效果 |
| B8 | 士兵耗尽但仍有可作战武将时编组继续存在；全员失能按已确认规则处理占位和行动 |
| B9 | 队列可跨轮继续，无有效行动不会卡住；一方全部失能正确结束，双方均失能正确处理 |
| B10 | P0/P1自动检查仍通过；可从开始完整操作到整场结果并明确重开 |

## 七、交付与阶段边界

交付：可运行测试战场、外部控制器、内部界面接入、自动检查、人工验收步骤及结果记录、Git基线。

不纳入本阶段：探索/城镇/迷宫、正式美术、AI自动选敌、技能、正式伤亡与指挥公式、磁盘存档、演出速度控制。Windows独立exe模板安装及导出验收为并行技术待办，不作为已经通过的验证。

P2通过后进入P3持续状态：正式伤亡分类、武将失能影响、无兵编组细节与存取；未定玩法需先对齐。
